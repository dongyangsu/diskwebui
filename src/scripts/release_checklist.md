# 版本发布检查清单（每次更新版本必做）

> 铁律：**每次更新版本（改代码 / 打新包 / 推 GitHub），必须同步更新对应的 Markdown 文件**，不能只推代码。

## 一、打包与源码同步
- [ ] `src/**` 同步为最新可部署源码（server.js / lib / public / scripts）
- [ ] 重新打包 `versions/vX.Y/diskwebui_vX.Y_src.tar.gz`（`diskwebui_vX.Y/` 前缀；排除 `data/`、`tls/`、`*.bak*`）
- [ ] 校验包内文件与线上源码**逐文件 md5 一致**

## 二、Markdown 必改项
- [ ] **`README.md`**
  - [ ] 版本表中的「当前版本」与说明
  - [ ] 版本更新说明（新增功能 / 问题修复 / 优化改进 / 其他改动）
  - [ ] 设备要求（管理端服务器 / PC / 安卓 / iOS / 目标机器）如有变化
  - [ ] 终端适配表（如新增实测分辨率或浏览器）
  - [ ] 标题下的「⚠️ 仅限内网使用」警示保留
- [ ] **`CHANGELOG.md`**《版本更新记录（更新修复及优化）》
  - [ ] 新增一条按**日期**分节的本版记录
  - [ ] 逐条写：新增功能 / 问题修复（**按类别分组 + 条数**）/ 优化改进 / 移除调整
  - [ ] 内容必须来自**真实 diff 或实际操作**，不许编造
- [ ] **`versions/README.md`**：版本归档表新增/更新该版本条目
- [ ] `docs/` 下的规划文档（如涉及架构/部署/接口变更）

## 三、测试与验证（推送前）
- [ ] 跑一遍 UI 回归：`node src/scripts/ui_suite.mjs`（65 项断言；HTTP 与 HTTPS 各一次）
- [ ] 打印/导出/导入抽验
- [ ] 多分辨率与多浏览器抽验（Chrome / Firefox / Safari 内核）

## 四、推送与校验
- [ ] 推送 `src/**`、`versions/vX.Y/*.tar.gz`、`README.md`、`CHANGELOG.md`、`versions/README.md`
- [ ] 远端校验：文件大小 / sha 与本地一致，提交记录可查

## 五、写法风格（用户明确）
- 文档可以**参考**外部示例的**格式与组织方式**，但**不要照抄**措辞或专有说法
- 正文使用**本项目自己的技术语言**：功能说明写清"入口 / 使用前提"，问题写"修复了…的问题"
